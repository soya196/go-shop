🛒 go-shop — แผนที่โค้ด

Shopping API ที่เขียนตามหลัก Clean Architecture แบบ domain-first · Go standard library ล้วน ไม่มี dependency ภายนอกสักตัว
เอกสารนี้ตอบ 2 คำถาม: “ไฟล์ไหนทำหน้าที่อะไร” และ “request เดินทางผ่านอะไรบ้างกว่าจะถึงที่เก็บข้อมูล”

🔑 กฎข้อเดียวที่ทำให้ทุกอย่างเข้าที่
ลูกศรการพึ่งพา ชี้เข้าด้านในเสมอ — ชั้นนอกรู้จักชั้นใน แต่ชั้นในไม่รู้จักชั้นนอก
แปลเป็นภาษาที่ตรวจได้: internal/<domain> ห้ามมีบรรทัด import ที่ชี้ไป adapter หรือ framework — และมี cmd/archlint คอยบังคับ

ส่วนที่ 3 🧅 ชั้น middleware — request ผ่านอะไรก่อนถึง handler

ประกอบใน httpapi.Routes() · เขียนจากในออกนอก แต่ทำงานจากนอกเข้าใน

// internal/httpapi/httpapi.go:145
var h http.Handler = mux
h = requestLog(a.log)(h)   // เขียนบรรทัดนี้ก่อน...
h = cors(a.cfg.AllowedOrigins)(h)
h = requestID(h)
h = recoverer(a.log)(h)    // ...แต่ตัวนี้ทำงานก่อน (อยู่นอกสุด)
recoverer — ดัก panic ทุกอย่าง → log stack trace แล้วตอบ 500 · stack ไม่หลุดไปหา client
requestID — รับ X-Request-Id จาก gateway ถ้ามี (ปฏิเสธถ้ายาวเกิน 128) ไม่มีก็สุ่มใหม่ → ใส่ลง context + ตอบกลับใน header
cors — ปิดโดย default · ตอบ preflight · ใส่ Vary: Origin เสมอ (กัน cache ปนกันระหว่าง origin)
requestLog — จับ status ด้วย statusRecorder → เลือก level ตามผล: 5xx=Error · 4xx=Warn · อื่นๆ=Info
http.ServeMux — pattern routing ของ Go 1.22+ — "POST /carts/{id}/items" · r.PathValue("id")
handler → Service → Entity — 💎 ตั้งแต่ตรงนี้เข้าไปคือโลกที่ไม่รู้จัก HTTP
⚠️ ข้อสังเกตสำคัญ — recoverer อยู่นอกสุด เพราะมันต้องดัก panic ที่เกิดใน middleware ตัวอื่นด้วย ถ้าเอาไปไว้ในสุด panic ที่เกิดใน requestLog จะทำให้ทั้ง process ตาย
📌 ยังไม่มี — และรู้ตัว: handler timeout (ตัดงานที่ช้าเกินก่อน WriteTimeout จะฟาด) · auth/RBAC · rate limit
ตอนนี้ตั้ง ReadHeaderTimeout 5s · ReadTimeout 15s · WriteTimeout 15s · IdleTimeout 60s ที่ cmd/api/main.go แต่ Go ไม่ฆ่า goroutine ของ handler ให้ — เกิน WriteTimeout แล้ว handler ยังวิ่งต่อ

ส่วนที่ 4 🚨 error จาก domain → HTTP status

แปลที่เดียวใน httpapi.fail() — domain ไม่รู้จักเลขสถานะ HTTP มันคืน error ที่มีความหมายทางธุรกิจ

🔑 ทำไมถึงสำคัญ — ถ้า domain คืน 404 เมื่อไหร่ แปลว่ามันรู้จัก HTTP แล้ว → เอาไปใช้กับ gRPC / CLI / batch job ไม่ได้อีก
ที่นี่ domain คืน catalog.ErrNotFound ส่วน การแปลเป็นเลข เป็นหน้าที่ของ adapter

statuserror จาก domainความหมาย

422ErrOutOfStock · ErrInactive · cart.ErrNotSellable
customer.ErrSuspended · ErrCreditTooLow · payment.ErrDeclined		รูปแบบถูก แต่กฎธุรกิจไม่ให้ผ่าน
400ErrInvalidName · ErrInvalidPrice · cart.ErrInvalidQty ฯลฯinput ผิดตั้งแต่ต้น
500อื่นๆ ทั้งหมดไม่รู้จัก → log ไว้ แล้วตอบกลางๆ
✅ 409 vs 422 — เส้นแบ่งที่ใช้จริง
409 Conflict = “ทำไม่ได้เพราะสถานะ” เช่น จ่ายเงินซ้ำ, ข้ามสถานะ (PAID → SHIPPED)
422 Unprocessable = “ทำไม่ได้เพราะกฎ” เช่น ของหมด, ลูกค้าโดนระงับ, บัตรถูกปฏิเสธ

ส่วนที่ 5 🛡️ กฎที่ cmd/archlint บังคับ

อ่าน go list -json ./... → เทียบกับ arch.json → exit 1 ถ้าผิด · รันใน CI และใน docker build

กฎห้ามอะไรgo build จับได้ไหม
domainMustNotImportLayersdomain → adapter/composition❌ จับไม่ได้ ถ้า adapter ไม่ import กลับ (เช่น clock, uid)
domainMustNotImportThirdPartydomain → lib ภายนอก❌ จับไม่ได้
domainStdlibDenyListdomain → net/http, database/sql ฯลฯ❌ จับไม่ได้
cross-domaindomain → domain อื่น (ยกเว้น money)❌ จับไม่ได้
bannedPackageNamesชื่อ util · common · helper · model · service❌ จับไม่ได้
unclassified-packagepackage ที่ไม่ได้ระบุชั้นใน arch.json❌ จับไม่ได้
วงจร importA → B → A✅ จับได้ฟรี — import cycle not allowed
⚠️ ข้อค้นพบที่ทำให้ archlint มีค่าจริง
คำพูดที่ว่า “Go บังคับทิศทางการพึ่งพาให้ฟรี” ถูก แต่ไม่ครบ — กลไกจริงคือ วงจร import ซึ่งเกิดเฉพาะเมื่ออีกฝั่ง import กลับ
ดังนั้น order → clock (adapter ที่ไม่ import order กลับ) compiler ยอมให้ผ่าน
ทดสอบแล้วโดยแทรกการละเมิด 4 แบบ: go build ผ่านหมด · archlint จับได้ทั้ง 4
✅ วิธีตรวจสถาปัตยกรรมด้วยมือ (ทำได้ทันทีโดยไม่ต้องมี archlint)
