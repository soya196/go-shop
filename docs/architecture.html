🛒 go-shop — แผนที่โค้ด production stack

Shopping API ที่เขียนตามหลัก Clean Architecture แบบ domain-first · gin + PostgreSQL + JWT + OpenTelemetry
เอกสารนี้ตอบ 2 คำถาม: “ไฟล์ไหนทำหน้าที่อะไร” และ “request เดินทางผ่านอะไรบ้างกว่าจะถึงที่เก็บข้อมูล”

📍 เอกสารนี้อธิบาย branch feat/production-stack — ถ้าอยากดูเวอร์ชัน zero-dependency (stdlib ล้วน ไม่มี gin/pgx) ให้ดูเอกสารเดียวกันบน branch main
โค้ด internal/<domain>/ ของสอง branch เกือบเหมือนกันทุกบรรทัด — นั่นคือประเด็นทั้งหมดของเอกสารนี้
🔑 กฎข้อเดียวที่ทำให้ทุกอย่างเข้าที่
ลูกศรการพึ่งพา ชี้เข้าด้านในเสมอ — ชั้นนอกรู้จักชั้นใน แต่ชั้นในไม่รู้จักชั้นนอก
แปลเป็นภาษาที่ตรวจได้: internal/<domain> ห้ามมีบรรทัด import ที่ชี้ไป adapter หรือ framework — และมี cmd/archlint คอยบังคับ

ส่วนที่ 3 🧅 ชั้น middleware — request ผ่านอะไรก่อนถึง handler

ประกอบใน httpapi.Routes() · gin เรียงตามลำดับที่ Use() ตรงๆ — อ่านจากบนลงล่างได้เลย (ต่างจากเวอร์ชัน stdlib ที่ต้องเขียนกลับหัว)

// internal/httpapi/httpapi.go:164
gin.SetMode(gin.ReleaseMode)   // ปิด log ของ gin — เราใช้ requestLog ของเราเอง
r := gin.New()                 // New ไม่ใช่ Default — Default ยัด middleware มาให้เอง

r.Use(recoverer(a.log), requestID(), cors(a.cfg.AllowedOrigins), requestLog(a.log))

if a.cfg.TracingEnabled {
  r.Use(otelgin.Middleware(name))   // หลัง requestID เพื่อให้ span มี request_id ติดไป
}

for _, rt := range a.routes() {
  if len(rt.roles) > 0 {
    r.Handle(rt.Method, ginPath(rt.Pattern), a.requireRole(rt.roles...), rt.handler)
    continue
  }
  r.Handle(rt.Method, ginPath(rt.Pattern), rt.handler)
}
recoverer — ดัก panic ทุกอย่าง → log stack trace แล้วตอบ 500 · stack ไม่หลุดไปหา client (เขียนเอง ไม่ใช้ gin.Recovery() เพราะอยากคุมรูปแบบ log)
requestID — รับ X-Request-Id จาก gateway ถ้ามี (ปฏิเสธถ้ายาวเกิน 128) ไม่มีก็สุ่มใหม่ → ใส่ลง context + ตอบกลับใน header
cors — ปิดโดย default · ตอบ preflight · ใส่ Vary: Origin เสมอ (กัน cache ปนกันระหว่าง origin)
requestLog — อ่าน status จาก c.Writer.Status() → เลือก level ตามผล: 5xx=Error · 4xx=Warn · อื่นๆ=Info
otelgin — 🔭 เปิดเมื่อตั้ง -trace · สร้าง span ตัวแม่ ของทั้ง request (GET /products) แล้ว span ของ SQL จะไปเกาะเป็นลูกเอง
requireRole — 🔐 ต่อเฉพาะ route ที่ต้องการ ไม่ใช่ global — อ่านจากคอลัมน์แรกของตาราง routes → 401 ถ้าไม่มี token · 403 ถ้าสิทธิ์ไม่พอ
gin router — radix tree · "/carts/:id/items" · c.Param("id") — มี ginPath() แปลง {id} ของ openapi เป็น :id ของ gin
handler → Service → Entity — 💎 ตั้งแต่ตรงนี้เข้าไปคือโลกที่ไม่รู้จัก HTTP และไม่รู้จัก gin
⚠️ ข้อสังเกตสำคัญ — recoverer อยู่นอกสุด เพราะมันต้องดัก panic ที่เกิดใน middleware ตัวอื่นด้วย ถ้าเอาไปไว้ในสุด panic ที่เกิดใน requestLog จะทำให้ทั้ง process ตาย
🔑 ทำไม handler ยังไม่ผูกกับ gin ทั้งที่ใช้ gin
Routes() คืน http.Handler เหมือนเดิม (gin.Engine implement interface นี้อยู่แล้ว) → เทส HTTP เดิม 812 บรรทัดผ่านโดยไม่ต้องแก้ เพราะมันยิงผ่าน httptest กับ http.Handler
ถ้าเทสเขียนแบบผูกกับ *gin.Context ตั้งแต่แรก การเปลี่ยน framework จะแพงทันที
📌 ยังไม่มี — และรู้ตัว: handler timeout · rate limit (ควรทำที่ gateway) · idempotency key
ตอนนี้ตั้ง ReadHeaderTimeout 5s · ReadTimeout 15s · WriteTimeout 15s · IdleTimeout 60s ที่ cmd/api/main.go แต่ Go ไม่ฆ่า goroutine ของ handler ให้ — เกิน WriteTimeout แล้ว handler ยังวิ่งต่อ

🔑 ทำไมไม่มี POST /auth/token
endpoint ที่แจก token ให้ใครก็ได้ = ช่องโหว่ที่ใหญ่กว่าการไม่มี auth เพราะดูเหมือนปลอดภัย
ของจริงต้องต่อกับ IdP (Keycloak / Auth0 / Cognito) — โปรเจกต์นี้เลยออก token ด้วย CLI แทน: 
go run ./cmd/token -secret "$JWT_SECRET" -role admin -sub adm_1
⚠️ ไม่ตั้ง -jwt-secret = auth ปิดทั้งระบบ — ตอนบูตจะ log WARN ว่า “ทุก endpoint เรียกได้โดยไม่ต้องมี token” · จงใจให้เป็นแบบนี้เพื่อให้ make run เล่นได้ทันที แต่ห้ามขึ้น production แบบนี้
✅ ช่องโหว่ที่เทสคุมไว้ (11 เคสใน auth_test.go) — ที่สำคัญที่สุดคือ alg=none: token ที่บอกว่า “ฉันไม่ได้เซ็นมา” ต้องถูกปฏิเสธ ไม่ใช่ผ่านเพราะลายเซ็นว่างตรงกับที่คำนวณได้
อื่นๆ: หมดอายุ · ลายเซ็นผิด · role แปลกปลอม · header ไม่มีคำว่า Bearer

ส่วนที่ 5 🚨 error จาก domain → HTTP status

แปลที่เดียวใน httpapi.fail() — domain ไม่รู้จักเลขสถานะ HTTP มันคืน error ที่มีความหมายทางธุรกิจ

🔑 ทำไมถึงสำคัญ — ถ้า domain คืน 404 เมื่อไหร่ แปลว่ามันรู้จัก HTTP แล้ว → เอาไปใช้กับ gRPC / CLI / batch job ไม่ได้อีก
ที่นี่ domain คืน catalog.ErrNotFound ส่วน การแปลเป็นเลข เป็นหน้าที่ของ adapter

✅ 409 vs 422 — เส้นแบ่งที่ใช้จริง
409 Conflict = “ทำไม่ได้เพราะสถานะ” เช่น จ่ายเงินซ้ำ, ข้ามสถานะ (PAID → SHIPPED)
422 Unprocessable = “ทำไม่ได้เพราะกฎ” เช่น ของหมด, ลูกค้าโดนระงับ, บัตรถูกปฏิเสธ
⚠️ กับดักที่เจอจริงตอนใส่ validation ของ gin
tag binding:"required" บนฟิลด์ int จะปฏิเสธค่า 0 เพราะ gin แยกไม่ออกระหว่าง “ไม่ได้ส่งมา” กับ “ส่ง 0 มา”
แต่ PATCH /carts/{id}/items/{productID} ที่ qty=0 แปลว่า “เอาสินค้าออก” ซึ่งถูกต้อง
→ ต้องใช้ binding:"gte=0" แทน · มีเทสคุมไว้ใน validation_test.go ไม่ให้ใครเผลอเปลี่ยนกลับ
